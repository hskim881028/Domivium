# Domivium 프로젝트 인프라 구성 개발일지

## 배경

Domivium 프로젝트는 Unity 클라이언트와 ASP.NET Core 서버로 구성된 온라인 게임 프로젝트입니다. 초기 개발 단계에서 로컬 개발 환경을 효율적으로 구축하기 위해 Docker Compose를 활용한 인프라를 구성했습니다.

## 인프라 구성 목표

1. **로컬 개발 환경의 빠른 구축**: 새로운 개발자가 프로젝트를 시작할 때 인프라 설정에 시간을 소비하지 않도록
2. **일관된 개발 환경**: 모든 개발자가 동일한 데이터베이스 및 캐시 환경에서 작업
3. **프로덕션 환경과의 유사성**: 로컬 환경이 프로덕션 환경과 유사한 구조를 가지도록
4. **확장 가능한 아키텍처**: 향후 확장이 용이한 구조로 설계

## 기술 스택 선택

### 데이터베이스: PostgreSQL 16

**선택 이유:**
- 강력한 관계형 데이터베이스 기능
- JSON/JSONB 타입 지원으로 유연한 데이터 모델링 가능
- 게임 서버에서 필요한 트랜잭션 및 데이터 무결성 보장
- Entity Framework Core와의 우수한 통합

### 캐시/세션 저장소: Redis 7

**선택 이유:**
- 고성능 인메모리 데이터 스토어
- 분산 락 구현에 필수적인 RedLock 알고리즘 지원
- 게임 서버의 세션 관리 및 캐싱에 최적화
- AOF(Append-Only File) 지속성으로 데이터 안정성 확보

### 서버 프레임워크: ASP.NET Core + MagicOnion

**선택 이유:**
- gRPC 기반의 고성능 통신
- MagicOnion으로 C# 개발자에게 친숙한 gRPC 구현
- HTTP/2 지원으로 네트워크 효율성 향상
- REST API와 gRPC를 동시에 제공할 수 있는 유연성

## Docker Compose 구성

### 전체 구조

```yaml:infra/docker-compose.yml
version: "3.9"

services:
  postgres:
    image: postgres:16
    container_name: local_postgres
    environment:
      POSTGRES_USER: domir
      POSTGRES_PASSWORD: 1234
      POSTGRES_DB: domivium
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - backend

  redis:
    image: redis:7-alpine
    container_name: local_redis
    ports:
      - "6379:6379"
    command: redis-server --appendonly yes --requirepass domivium_redis_2024
    volumes:
      - redisdata:/data
    networks:
      - backend
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:

networks:
  backend:
    driver: bridge
```

### 주요 설계 결정사항

#### 1. 네트워크 분리
- `backend` 네트워크를 별도로 구성하여 서비스 간 통신을 격리
- 향후 추가 서비스 확장 시 네트워크 정책 관리 용이

#### 2. 볼륨 영속성
- PostgreSQL과 Redis 모두 Named Volume을 사용하여 데이터 영속성 보장
- 컨테이너 재시작 시에도 데이터 손실 방지

#### 3. Redis 보안 설정
- 프로덕션 환경과 유사하게 비밀번호 인증 적용
- AOF 활성화로 데이터 영속성 확보
- `restart: unless-stopped`로 안정성 향상

## 서버 애플리케이션 구성

### 이중 엔드포인트 전략

게임 서버의 특성상 gRPC의 고성능과 REST API의 편의성을 모두 제공해야 했습니다.

```json:src/Domivium.Server/appsettings.json
"Kestrel": {
  "Endpoints": {
    "Grpc": {
      "Url": "http://localhost:5000",
      "Protocols": "Http2"
    },
    "RestApi": {
      "Url": "http://localhost:5001",
      "Protocols": "Http1"
    }
  }
}
```

**gRPC 엔드포인트 (포트 5000)**
- 게임 클라이언트의 주요 통신 경로
- HTTP/2 기반의 이진 프로토콜로 높은 성능
- 프로토버프를 통한 타입 안전성

**REST API 엔드포인트 (포트 5001)**
- 관리자 도구 및 개발/디버깅 용도
- HTTP/1 기반으로 브라우저에서 직접 테스트 가능
- JSON 기반의 직관적인 API

### 서비스 등록 전략

확장 가능하고 유지보수가 쉬운 구조를 위해 확장 메서드 패턴을 사용했습니다.

```cs:src/Domivium.Server/Program.cs
builder.Services
    .AddPostgresql(builder.Configuration)
    .AddRedis(builder.Configuration)
    .AddJwtAuth(builder.Configuration)
    .AddMagicOnionWithFilters()
    .AddAppServicesScoped()
    .AddAppServicesSingleton();
```

각 확장 메서드는 특정 책임만 담당하여 코드의 가독성과 테스트 용이성을 높였습니다.

### PostgreSQL 연결 설정

```cs:src/Domivium.Server/Extensions/ServiceCollectionExtensions.cs
public static IServiceCollection AddPostgresql(this IServiceCollection services, IConfiguration config)
{
    services.AddDbContext<AppDbContext>((sp, opt) =>
    {
        var cs = config.GetConnectionString("Default") 
            ?? throw new InvalidOperationException("ConnectionStrings:Default is missing.");
        opt.UseNpgsql(cs);

        foreach (var interceptor in sp.GetServices<SaveChangesInterceptor>())
        {
            opt.AddInterceptors(interceptor);
        }
    });
    return services;
}
```

**주요 특징:**
- Entity Framework Core의 인터셉터 패턴 활용
- Post-commit 작업을 위한 커스텀 인터셉터 지원
- 설정 누락 시 명확한 예외 메시지 제공

### Redis 연결 및 분산 락

```cs:src/Domivium.Server/Extensions/ServiceCollectionExtensions.cs
public static IServiceCollection AddRedis(this IServiceCollection services, IConfiguration config)
{
    services.AddSingleton<IConnectionMultiplexer>(_ =>
    {
        var cs = config.GetConnectionString("Redis") 
            ?? throw new InvalidOperationException("ConnectionStrings:Redis is missing.");
        return ConnectionMultiplexer.Connect(cs);
    });

    services.AddSingleton<RedLockFactory>(sp =>
    {
        var mux = sp.GetRequiredService<IConnectionMultiplexer>();
        return RedLockFactory.Create([new RedLockMultiplexer(mux)]);
    });
    return services;
}
```

**주요 특징:**
- `ConnectionMultiplexer`를 싱글톤으로 관리하여 연결 풀 최적화
- RedLock 알고리즘을 통한 분산 환경에서의 안전한 락 구현
- 게임 서버의 동시성 제어에 필수적인 기능

### JWT 인증 구성

게임 서버의 특성상 세션 관리와 인증이 중요했습니다. JWT를 선택한 이유:

1. **스케일아웃 친화적**: 서버 인스턴스 간 상태 공유 불필요
2. **클라이언트-서버 통신 최적화**: 매 요청마다 세션 조회 불필요
3. **표준 프로토콜**: 다양한 클라이언트와의 호환성

```cs:src/Domivium.Server/Extensions/ServiceCollectionExtensions.cs
public static IServiceCollection AddJwtAuth(this IServiceCollection services, IConfiguration config)
{
    services.Configure<JwtSettings>(config.GetSection("Jwt"));
    
    var jwtSettings = config.GetSection("Jwt").Get<JwtSettings>();
    var validationParameters = new TokenValidationParameters
    {
        ValidateIssuer = true,
        ValidateAudience = true,
        ValidateLifetime = true,
        ValidateIssuerSigningKey = true,
        ValidIssuer = jwtSettings.Issuer,
        ValidAudience = jwtSettings.Audience,
        IssuerSigningKey = new SymmetricSecurityKey(
            Encoding.UTF8.GetBytes(jwtSettings.SecretKey)),
        ClockSkew = TimeSpan.FromSeconds(jwtSettings.ClockSkewSeconds)
    };
    
    services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
        .AddJwtBearer(options => options.TokenValidationParameters = validationParameters);
    
    return services;
}
```

### MagicOnion 필터 체인

MagicOnion의 필터 패턴을 활용하여 크로스 커팅 관심사를 효과적으로 처리했습니다.

```cs:src/Domivium.Server/Extensions/ServiceCollectionExtensions.cs
services.Configure<MagicOnionOptions>(opt =>
{
    opt.GlobalFilters.Add(new MagicOnionServiceFilterDescriptor(typeof(ExceptionFilterAttribute)));
    opt.GlobalFilters.Add(new MagicOnionServiceFilterDescriptor(typeof(AuthenticationFilterAttribute)));
    opt.GlobalFilters.Add(new MagicOnionServiceFilterDescriptor(typeof(UserLockFilterAttribute)));
    opt.GlobalFilters.Add(new MagicOnionServiceFilterDescriptor(typeof(UnitOfWorkFilterAttribute)));
});
```

**필터 체인 순서:**
1. **ExceptionFilter**: 모든 예외를 일관된 형식으로 처리
2. **AuthenticationFilter**: JWT 토큰 검증 및 사용자 인증
3. **UserLockFilter**: 사용자별 락을 통한 동시 요청 제어
4. **UnitOfWorkFilter**: 트랜잭션 및 데이터베이스 작업 관리

## 개발 워크플로우

### 초기 설정

1. **Docker Compose 실행**
   ```bash
   docker-compose -f infra/docker-compose.yml up -d
   ```

2. **서버 애플리케이션 실행**
   ```bash
   dotnet run --project src/Domivium.Server
   ```

3. **데이터베이스 자동 생성**
   - `Program.cs`에서 `db.Database.EnsureCreated()`를 통해 개발 중 자동으로 스키마 생성

### 일상적인 개발

- Docker Compose 컨테이너는 백그라운드에서 실행
- 서버 애플리케이션 재시작 시 자동으로 데이터베이스 연결
- 볼륨을 통한 데이터 영속성으로 컨테이너 재시작해도 데이터 유지

## 배운 점

1. **Docker Compose의 강점**
   - 로컬 개발 환경 구성이 매우 간단해짐
   - 새로운 팀원 온보딩 시간 대폭 단축

2. **확장 메서드 패턴의 유용성**
   - 서비스 등록 로직의 가독성 향상
   - 단위 테스트 작성이 용이함

3. **인프라 코드화의 중요성**
   - 설정 변경 사항을 버전 관리로 추적 가능
   - 환경 간 일관성 유지

## 결론

Docker Compose와 ASP.NET Core를 활용한 인프라 구성으로 안정적이고 확장 가능한 개발 환경을 구축할 수 있었습니다. 특히 확장 메서드 패턴과 필터 체인을 통한 서비스 구성은 코드의 유지보수성을 크게 향상시켰습니다.

앞으로는 프로덕션 환경 구성을 위한 추가 검토와 성능 최적화에 집중할 예정입니다.
